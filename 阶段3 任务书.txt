## 二、本阶段总体目标

本阶段新增五个核心能力：

1. 多资产投资组合与再平衡。
2. 深度风险分析与压力测试。

# 三、模块 A：多资产投资组合与再平衡

### A1. 组合创建

允许用户创建、保存和编辑投资组合。

每个组合至少包含：

- 组合名称和描述。
- 资产列表。
- 目标权重。
- 初始资金。
- 现金保留比例。
- 再平衡频率。
- 适用的数据集及回测区间。
- 交易成本与风险限制。

首版默认只允许现金账户，不启用杠杆和做空。

### A2. 资产配置方法

至少实现以下三种方法：

**方法一：等权重配置**

将资金按照相同权重分配给选定资产。

**方法二：用户指定权重**

用户自行输入每个资产的目标权重。

**方法三：逆波动率配置**

根据历史波动率的倒数构造资产权重，并在规定的权重约束下进行归一化。

对于所有方法，必须检查权重是否合法、总权重是否符合配置规则，以及现金比例是否满足约束。

均值—方差优化可以作为可选的进阶功能，但只有在基础组合回测正确之后才实施。

### A3. 再平衡

- 支持月度、季度等固定频率再平衡。
- 支持设定初始配置及后续目标权重。
- 根据当时可用的历史信息计算目标权重。
- 再平衡应产生实际的模拟订单，而不是直接修改持仓比例并忽略交易成本。
- 扣除手续费和滑点。
- 保留现金、持仓、订单及每次再平衡记录。
- 无可用价格的资产不能被假设为可以正常成交。
- 处理不同资产交易日不一致的问题。
- 对缺失行情、停牌或历史数据不足的资产明确提示。

禁止使用完整回测区间的数据提前计算每个历史时点的资产权重。

### A4. 组合比较

允许用户在相同回测区间、相同初始资金和一致成本假设下比较：

- 单资产投资。
- 等权重组合。
- 用户指定权重组合。
- 逆波动率组合。
- 现有策略生成的资产配置结果。

至少展示：

- 组合净值曲线。
- 各资产权重。
- 各资产收益贡献。
- 组合收益和风险指标。
- 交易成本。
- 最大回撤及发生区间。

所有数据必须来自真实的组合计算和交易记录。

# 四、模块 B：高级风险分析与压力测试

### B1. 风险指标

在阶段 2 已有指标基础上，检查并完善：

- 总收益率和年化收益率。
- 年化波动率。
- 夏普比率。
- 索提诺比率。
- 最大回撤。
- 卡玛比率。
- Beta 和基准超额收益。
- 下行波动率。
- 换手率。
- 交易成本占比。

对于每个指标，明确计算公式、数据要求、年化假设和适用限制。

当样本不足、标准差为零或分母无效时，返回明确的不可计算状态，不得产生虚假数值。

### B2. 回撤分析

- 展示完整回撤曲线。
- 标记最大回撤发生时间。
- 记录回撤开始日期、谷底日期及恢复日期。
- 区分已经恢复的回撤和回测结束时仍未恢复的回撤。
- 支持分析不同时间段的回撤情况。
- 不得在缺少完整恢复数据时伪造恢复日期。

### B3. 历史区间分析

将回测结果划分为不同时间段，分析策略在各区间内的表现。

- 按年、季度或用户指定区间查看结果。
- 比较不同区间的收益、波动率和最大回撤。
- 标记表现明显变化的区间。
- 显示每个区间的样本数量及数据覆盖情况。

如果只有模拟数据，必须明确标注模拟数据，不得将人为生成的区间解释为真实历史市场事件。

### B4. 压力测试

至少支持以下压力测试方式：

1. 手续费上升。
2. 滑点上升。
3. 延迟成交。
4. 降低资金使用率。
5. 改变再平衡频率。
6. 对指定历史区间进行独立回测。
7. 对指定资产施加用户配置的价格冲击情景。

对于每种情景，展示基准结果、压力情景结果及其差异。

历史压力测试必须使用真实可用的历史行情数据；假设价格冲击必须标记为人为设定的情景。

不得将假设情景描述为真实市场发生过的事件。

### B5. 风险预警

- 允许用户设置最大回撤、波动率等预警阈值。
- 展示触发时间、实际指标和对应阈值。
- 支持比较不同策略的风险表现。
- 风险预警和强制平仓必须明确区分。
- 本阶段默认只生成预警，不擅自改变既有策略的交易行为。

# 五、模块 C：策略参数优化

### C1. 优化目标

让用户能够针对已有策略搜索不同参数，并分析参数变化对结果的影响。

首批支持：

- 均线交叉策略的快线、慢线窗口。
- RSI 策略的窗口及阈值，前提是 RSI 策略已实现并通过测试。
- 机器学习信号策略的预测阈值和持有条件。
- 再平衡频率和仓位配置参数。

如果某种策略尚未实现，不得仅创建界面选项就宣称支持优化。

### C2. 搜索方式

首版实现简单的网格搜索，并提供合理的搜索范围限制。

- 用户可配置参数范围。
- 自动排除不合法的参数组合。
- 快线窗口必须小于慢线窗口。
- 设置最大实验组合数量。
- 显示排队状态、运行进度和失败原因。
- 避免在 Streamlit 主线程中长时间执行大量计算。
- 复用现有任务机制；如确实需要扩展，优先使用简单可靠的方式。

不得无上限地执行参数组合搜索。

### C3. 优化目标

允许用户选择适合的优化指标，例如：

- 验证区间夏普比率。
- 验证区间最大回撤约束。
- 验证区间收益。
- 风险调整后的收益指标。

支持设置最大回撤上限、最低交易次数等约束。

不允许仅依据测试集的最佳收益选择最终参数。

### C4. 参数敏感性分析

展示：

- 参数组合与对应指标。
- 不同参数组合的收益和风险。
- 参数变化对结果的影响。
- 不同区间下参数表现是否稳定。

重点识别只在单一参数点表现异常优秀、邻近参数表现明显恶化的情况。

不能因为某一组参数的历史收益最高，就将其直接认定为最优的实盘策略。

# 六、模块 D：滚动验证与策略稳健性分析

这是本阶段最重要的模块之一。

### D1. 滚动验证

在现有时间序列训练和测试机制上，增加滚动样本外验证能力。

优先支持：

- 固定长度训练窗口的滚动验证。
- 扩展训练窗口的滚动验证。
- 多个连续测试窗口的结果汇总。

每个窗口必须保存：

- 训练区间。
- 验证区间。
- 测试区间。
- 标签覆盖区间。
- 使用的数据版本。
- 训练参数及评估指标。

必须确保训练数据严格早于对应测试区间，且不会因为未来标签重叠而发生信息泄漏。

### D2. 参数优化与样本外评估隔离

严格区分：

- 训练数据。
- 参数选择使用的验证数据。
- 最终测试数据。
- 滚动样本外评估数据。

如果测试集已经参与参数选择，就不能继续把它当作完全独立的最终测试数据使用。必须明确标记测试集是否已经参与参数选择，并在实验记录中保留这一信息。

参数优化只能使用训练数据和指定的验证数据。最终测试集只能在策略和参数确定后用于最终评估。

如果已经反复查看测试集结果并据此修改策略，应明确说明测试集已不再完全独立，不能继续把它作为无偏的最终评估依据。

滚动样本外评估必须按照时间顺序逐个窗口执行。每个窗口只能使用当时已经可获得的数据训练模型、选择参数和生成交易信号。

### D3. 策略稳健性分析

对每个策略至少提供以下分析：

1. 不同时间区间的表现。
2. 不同手续费和滑点假设下的表现。
3. 不同参数组合下的表现。
4. 不同训练窗口长度下的表现。
5. 不同资产或资产组合上的表现（数据允许时）。
6. 不同市场阶段的表现（只有存在可靠历史数据和明确划分依据时）。

输出内容至少包括：

- 各测试窗口的收益率。
- 各窗口的夏普比率和最大回撤。
- 各窗口的交易次数。
- 样本外结果的均值、中位数和离散程度。
- 正收益窗口占比。
- 最差窗口表现。
- 交易成本变化对结果的影响。

不得只展示多个窗口合并后的平均收益，而忽略个别窗口的大幅亏损。

不得根据某一个表现优异的时间区间就宣称策略具有普遍有效性。

### D4. 过拟合与策略筛选偏差

系统应提供基础的过拟合风险提示：

- 比较训练集、验证集和测试集表现。
- 检查相邻参数组合的表现是否稳定。
- 记录总共尝试过多少个参数组合和策略实验。
- 标记测试集被反复查看或参与参数筛选的情况。
- 提示多次试验可能导致策略筛选偏差。
- 对交易次数过少、样本不足或收益集中在少数交易中的策略给出警告。

如果未来需要增加 Deflated Sharpe Ratio、概率夏普比率或其他高级统计检验，应先核对其数学定义、适用条件和实现方式，不得仅增加指标名称而没有正确计算。

### D5. 稳健性报告

为每次滚动验证生成独立报告，记录：

- 策略版本。
- 参数选择规则。
- 训练、验证和测试时间范围。
- 每个窗口的数据量。
- 样本外绩效。
- 交易成本假设。
- 过拟合风险提示。
- 实验限制和未解决的问题。

报告应区分历史回测、滚动样本外结果和假设情景，不得将它们混为一谈。

# 七、模块 E：统一实验管理与高级结果比较

在现有实验管理机制上扩展，不能重复创建一套互不兼容的数据库和记录体系。

### E1. 统一实验档案

所有实验都应能够关联：

- 数据集及其版本。
- 技术指标配置。
- 特征工程配置。
- 模型及参数。
- 策略版本。
- 回测配置。
- 组合配置（如适用）。
- 参数优化记录。
- 滚动验证记录。
- 绩效指标和风险分析。
- 报告文件及生成时间。

每次实验必须具有唯一 ID。

修改参数后应创建新的实验或版本，不能覆盖原始结果。

### E2. 多实验比较

提供实验对比界面，允许用户选择多个实验并比较：

- 总收益率。
- 年化收益率。
- 夏普比率。
- 最大回撤。
- 年化波动率。
- 交易次数。
- 换手率。
- 交易成本。
- 样本外表现。
- 数据覆盖区间。

比较时必须提示数据集、测试区间、手续费和滑点假设是否一致。

如果实验条件不同，应明确展示差异，不能直接把结果排名当成公平比较。

### E3. 研究结果追踪

- 展示实验创建时间和运行状态。
- 支持查看历史配置。
- 支持重新运行实验。
- 支持失败任务重试。
- 保存失败原因和错误日志。
- 记录数据版本或代码版本变化。
- 不允许静默修改历史结果。

如果原始数据已经更新，重新运行时必须允许用户明确选择使用旧版本还是新版本。

### E4. 实验导出

支持导出：

- 实验配置。
- 参数搜索结果。
- 滚动验证结果。
- 绩效指标。
- 交易明细。
- 组合权重和风险分析。
- HTML 研究报告。
- CSV 数据表。

导出的报告必须与页面实际展示的结果一致，并包含实验 ID、数据版本、时间区间和主要假设。

# 九、工程质量与性能要求

### 9.1 架构

- 核心计算逻辑与 Streamlit 页面分离。
- 组合优化、参数搜索、滚动验证和风险分析应具有独立且可测试的函数或服务。
- 复用阶段 1、阶段 2 已有的回测引擎、指标计算和数据访问接口。
- 不得重复实现已有功能并造成计算结果不一致。
- 对数据库新增字段和表结构，使用可追踪的迁移方式。
- 保留旧数据兼容性。

### 9.2 性能

- 参数搜索应设置最大组合数量。
- 对重复计算进行合理缓存，但必须考虑数据版本和参数变化。
- 耗时任务不得长期阻塞页面交互。
- 提供任务取消、错误恢复和合理的资源限制。
- 优先使用现有任务执行机制，不要无必要地引入复杂分布式基础设施。

### 9.3 安全与数据保护

- 不连接真实交易账户。
- 不执行真实交易。
- 不擅自发送外部付费请求。
- 不将 API 密钥写入代码或日志。
- 不删除现有数据集和实验记录。
- 不覆盖用户已有配置。
- 不执行未经授权的 Git 提交、推送或破坏性命令。

# 十、自动化测试与验收标准

必须在现有 79 个测试的基础上增加测试，而不是替换原有测试或降低断言标准。

具体测试数量由实际实现决定，不得为了达到某个数量而编写没有验证价值的测试。

## A. 投资组合测试

- 权重合法性和归一化。
- 不同资产的交易日对齐。
- 现金余额与持仓变化。
- 再平衡订单生成。
- 手续费和滑点计算。
- 缺失行情处理。
- 组合净值与单资产结果的一致性检查。

## B. 风险分析测试

- 最大回撤的手算对照。
- 回撤起始、谷底和恢复日期。
- 年化指标的适用条件。
- 零波动和样本不足的异常情况。
- 压力情景与基准情景的差异。
- 不可计算指标的明确状态。

## C. 参数优化测试

- 搜索空间边界。
- 非法参数组合排除。
- 最大搜索组合数量。
- 最优参数的选择规则。
- 验证集与测试集的隔离。
- 相同输入得到一致结果。

## D. 滚动验证测试

- 每个窗口严格遵守时间顺序。
- 训练集与测试集不存在不允许的时间重叠。
- 未来标签不会跨越隔离边界污染训练过程。
- 每个窗口独立拟合预处理器。
- 每个窗口使用当时可获得的数据训练模型。
- 最终测试结果不参与参数选择。
- 测试集被反复使用时产生明确警告。

## E. 回归测试

- 阶段 1 的数据采集、数据清洗和自动分析功能保持正常。
- 阶段 2 的技术指标、机器学习和回测功能保持正常。
- 现有数据库记录可以正常读取。
- 现有页面能够正常渲染。
- 应用能够从当前启动脚本正常启动。
- 现有实验和回测记录不丢失。

必须执行真实测试并记录结果。

如果某项测试失败，应说明失败原因、影响范围和修复计划，不得通过删除测试、跳过测试或修改断言来制造通过结果。

# 十一、分阶段实施顺序

本阶段可以拆分为以下内部里程碑，但都属于 QuantLab 阶段 3。

### 里程碑 3A：投资组合与再平衡

完成组合创建、权重配置、多资产回测、再平衡和交易成本核算。

验收后再进入下一项。

### 里程碑 3B：高级风险分析

完成风险指标核验、回撤分析、历史区间分析和压力测试。

### 里程碑 3C：参数优化

完成有限搜索空间、参数组合运行、验证集选参和结果比较。

### 里程碑 3D：滚动样本外验证

完成滚动窗口、参数隔离、样本外统计和过拟合风险提示。

### 里程碑 3E：统一实验管理与报告

完成实验关联、结果比较、历史记录追踪和研究报告导出。

每个里程碑完成后：

1. 运行相关新增测试。
2. 运行现有全部测试。
3. 检查页面渲染。
4. 验证真实计算结果。
5. 更新交付文档。
6. 汇报已完成内容、失败项和已知限制。

不要为了追求开发速度一次性堆砌全部模块。
